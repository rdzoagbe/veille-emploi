# Independent mailbox integration — v0.14.0 pilot

## Available without registration
All authenticated users can select up to ten .eml files (1 MiB each) from Gmail, Outlook or another provider. The browser requires consent before sending files to the authenticated API. The API parses them transiently, classifies recruitment events, and stores only relevant application history; it does not retain raw message bodies or attachments, send confirmation emails, or change the original mailbox. Ambiguous or unsupported messages are counted as review items. Unknown application dates are not guessed. The existing personal Gmail label import is unchanged. There is a 100 selected-message attempts/day per-account limit (best-effort count plus reservation; not an atomic anti-abuse limiter).

## Direct Outlook pilot (disabled by default)
The app implements Microsoft OAuth 2.0 authorization code + PKCE for a public SPA client, with a fixed production redirect. This pilot is on-demand only: the user connects and explicitly imports the root folder named veille-candidatures, up to 20 messages from the preceding 90 days per click. No refresh tokens are requested or stored. Microsoft returns a short-lived delegated access token; it stays only in the browser's memory and is discarded on local disconnect, sign-out, reload or expiry. The only authorization state persisted is a one-time, 10-minute PKCE transaction in sessionStorage, bound to the app session. Microsoft consent is mailbox-wide read-only; the implemented reader only lists folder names, finds the designated folder, and reads text from that folder on demand. It does not read attachments or send/delete/change email. Only message text and limited metadata are sent to the app API to classify and store application history. The Microsoft profile email must equal the existing verified Veille Emploi account email. The API treats imported text as user-provided content scoped to that user's account, not as a privileged identity assertion.

### One-time Microsoft configuration
1. Open Microsoft Entra admin center > App registrations > New registration.
2. Register Veille Emploi with supported account types: accounts in any organizational directory and personal Microsoft accounts.
3. Add the **Single-page application** platform redirect URI exactly `https://rdzoagbe.github.io/veille-emploi/`. Do not use Web platform, client secrets, implicit flow or wildcard redirect.
4. Configure Microsoft Graph delegated permissions **User.Read** and **Mail.Read** only; do not request Mail.ReadWrite, Mail.Send, application permissions or offline_access. Some work/school organizations require administrator consent. Review the app's consent/privacy disclosures and test with consenting accounts before broader release.
5. Set only the public Application (client) ID as `OUTLOOK_SPA_CLIENT_ID` in the Veille Emploi Supabase Edge Function secrets. Do not store credentials or change the Gmail secrets. The app hides/disables direct connection until the API returns a valid ID. If provider configuration fails or the PWA browser does not preserve sessionStorage through the redirect, the .eml import remains available.
6. Test with a dedicated Outlook test mailbox whose email matches a verified app account. Make the root folder and move only synthetic recruitment messages into it. Check state replay, account mismatch, expired token, cancel, no-folder, pagination, refusal to read other folders, cross-account import and local disconnect. Revoke consent in Microsoft account if desired.
7. No background Outlook sync is implemented yet; persistent delegated refresh tokens, encrypted storage, scheduling/rotation/revocation and provider-specific reviews would be a separate phase.

## Gmail public OAuth decision
Gmail readonly is a restricted Google scope. Public OAuth verification and server-side restricted-data security assessment may require external costs. Testing refresh tokens for external apps typically expire in seven days. Keep existing personal pilot and selected-file route; do not enable unapproved direct Gmail access or ask users for app passwords. See https://developers.google.com/workspace/gmail/api/auth/scopes and https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification.

## Privacy
A user controls which files or folder messages are submitted; do not upload unrelated mail or files with sensitive attachments. Original recruitment messages are not persisted by this import flow. Imported application metadata is account-scoped and can be corrected or deleted through the existing UI. Local Outlook disconnect drops the token, not the provider-side consent grant. Users can revoke that grant via Microsoft. The legacy Gmail label import retains its separate owner-only configuration.
